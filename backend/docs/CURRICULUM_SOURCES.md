# Curriculum scope and source notes

Nebula's branch catalog is a **common reference outline**, not a claim that every Indian university teaches the same subjects, topics, semester order, credits, or assessment pattern. Institutions revise model curricula and offer local electives. Students should match these tracks to their own current syllabus before using them for exam planning.

For Information Technology, BCA, and specialist tracks where the selected AICTE documents do not provide a directly matching branch model, Nebula labels the included topics as common foundations. They need institution-specific mapping before semester/exam use.

## Files

- `../data/curriculum_tracks.csv`: supported degree/branch identifiers and the scope statement shown in the app.
- `../data/course_tracks.csv`: links existing Nebula courses to relevant tracks.
- `../data/branch_curriculum.csv`: track-specific course rows and topic outlines. `|` separates topics in this source CSV.
- `../scripts/build_branch_curriculum.py`: deterministic generator for shared engineering foundation rows and track course identifiers.
- `../scripts/build_core_course_practice.py`: deterministic outline and question authoring source for 25 shared computing catalog subjects. It preserves the first five topic IDs per course so pilot lesson links remain stable, and keeps the five expanded pilot quiz sets reproducible.
- `../scripts/expand_foundation_bca_practice.py`: repeatable, original practice pack for shared B.Tech foundations and BCA.
- `../scripts/expand_computing_practice.py`: repeatable, original question packs for computing and selected B.Tech branch subjects. The items are Nebula-authored drafts, not copied PrepInsta/GeeksforGeeks questions; all require qualified subject review before being treated as exam-ready material.
- `../data/practice_question_bank.csv`: CSV-backed, topic-linked focused questions with answer keys, explanations, and per-question review evidence (`review_status`, `reviewer_name`, `reviewer_role`, `source_url`, `review_notes`, `review_date`). New rows are pending by default. Mark a row `approved` only after a qualified instructor or subject-matter expert checks the answer, explanation, and topic mapping and adds their name, role (`instructor` or `subject_matter_expert`), review date (`YYYY-MM-DD`), and an HTTPS source. Use `needs_revision` when a correction is required; quizzes containing such a row are hidden from students until corrected. The backend validates the required evidence and only displays an instructor-reviewed quiz status when every question in that quiz is approved. Reviewer details are self-reported in this workflow and are not independently verified by Nebula.
- `../data/courses.csv`, `../data/topics.csv`, `../data/topic_prerequisite.csv`: existing curriculum import inputs. Current synthetic legacy topic rows are retained for compatibility and should be progressively replaced with reviewed outlines.

The authored catalog currently includes 36 track choices (35 B.Tech branch/specialization IDs and BCA) and 522 track-to-course rows across 147 unique branch-outline courses. In addition, the legacy computing catalog has concrete five-topic outlines for 25 shared subjects. Many tracks still have only a foundation plus a small set of core subject outlines; this is a useful MVP catalog, not all subjects across all eight semesters. The lesson seeder still publishes in-app lessons for a small pilot set. The question bank contains 2,595 explained questions across 172 quiz sets, with at least 15 questions in every set and at least three distinct questions for each of the 860 active course-topic pairs. The question records pass structural and course/topic-linkage checks; every row remains pending external instructor review. This is starter practice coverage, not a complete or instructor-certified exam-preparation bank.

The added track outlines and questions are Nebula-authored drafts, not copied AICTE or online question-bank text. New question content has not had external instructor review and must not be presented as formal exam material. To publish the CSV bank into MongoDB, deploy the code and run `python scripts/seed_learning_content.py` from `backend/` with the production database environment configured. The seeder extends only a published, unedited source-controlled quiz whose stored question sequence is an exact prefix of the CSV; admin-edited quizzes are preserved. A course/topic outline does not by itself provide enough depth for a complete degree, GATE, placement, or university exam preparation product.
